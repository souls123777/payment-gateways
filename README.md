# payment-gateways

Первый шаг небольшого сервиса приёма платежей. Консольная команда принимает способ оплаты и сумму, а сервис выбирает платёжный шлюз по способу оплаты и проводит платёж.

Symfony 7.4, PHP 8.3+, гексагональная архитектура, паттерны **Strategy** и **Factory**. Пока без HTTP и без базы данных: шлюзы это детерминированные заглушки, поэтому результат легко проверить руками.

## Запуск

Нужны PHP 8.3+ и Composer.

```bash
composer install
php bin/console app:payment:pay card 150000 RUB
```

Аргументы команды `app:payment:pay`:

| Аргумент | Значение |
|---|---|
| `method` | способ оплаты: `card`, `sbp`, `wallet` |
| `amount` | сумма **в минорных единицах** (копейках, центах): `150000` это 1500.00 RUB |
| `currency` | валюта: `RUB` (по умолчанию), `USD`, `EUR` |

Примеры:

```bash
php bin/console app:payment:pay card 150000 RUB   # одобрен
php bin/console app:payment:pay sbp 100 USD       # отказ: currency_not_supported
php bin/console app:payment:pay wallet 2000000    # отказ: limit_exceeded
php bin/console app:payment:pay crypto 100        # ошибка ввода: неизвестный способ оплаты
```

Коды выхода:

| Код | Когда |
|---|---|
| 0 | платёж одобрен |
| 1 | платёж отклонён шлюзом или для способа оплаты не нашлось шлюза |
| 2 | некорректный ввод (неизвестный способ или валюта, сумма не целая или не положительная) |

Поведение шлюзов-заглушек:

| Шлюз | Лимит одного платежа | Валюты |
|---|---|---|
| `card` | 500 000.00 | любая |
| `sbp` | 100 000.00 | только RUB |
| `wallet` | 15 000.00 | любая |

## Паттерны

**Strategy.** Интерфейс `PaymentGateway` (`supports()` и `pay()`) описывает способ принять деньги. Каждый шлюз (`CardGateway`, `SbpGateway`, `WalletGateway`) это отдельная стратегия со своими правилами.

**Factory.** Порт `PaymentGatewayFactory` отдаёт шлюз по способу оплаты, реализация `TaggedPaymentGatewayFactory` выбирает первый шлюз, который заявил `supports()`. Шлюзы собирает контейнер Symfony через тег `app.payment_gateway` (`_instanceof` и `!tagged_iterator` в `config/services.yaml`). Чтобы добавить шлюз, достаточно написать один класс: фабрика, use case и конфигурация не меняются.

## Архитектура

Гексагональная: зависимости направлены внутрь, домен ничего не знает о Symfony.

```
src/
├── Domain/Payment/          # деньги и результат платежа: чистый PHP, без фреймворка
│   ├── Money, Currency, PaymentMethod, PaymentStatus, DeclineReason, PaymentResult
│   └── Exception/InvalidMoneyException
├── Application/Payment/     # сценарий и порты
│   ├── ProcessPayment       # use case
│   ├── Port/PaymentGateway, Port/PaymentGatewayFactory
│   └── Exception/PaymentGatewayNotFoundException
├── Infrastructure/Payment/  # исходящие адаптеры
│   ├── Gateway/CardGateway, SbpGateway, WalletGateway
│   └── TaggedPaymentGatewayFactory
└── UI/Console/              # входящий адаптер: ProcessPaymentCommand
```

Порты `PaymentGateway` и `PaymentGatewayFactory` объявлены в слое приложения, а привязка порта к адаптеру сделана в одном месте, в `config/services.yaml`.

## Принятые решения

- **Деньги это целое число минорных единиц.** `float` не подходит: он не хранит суммы точно. Валюта едет вместе с суммой в `Money`.
- **Отказ шлюза это результат, а не исключение.** Исключения остаются для ошибок: невалидная сумма, отсутствующий шлюз.
- **Свои статусы.** Сейчас это `approved` и `declined`. Каждый шлюз приводит ответ провайдера к ним, и остальной код не зависит от провайдеров.
- **Константы лежат рядом с кодом**: константы классов и enum'ы, без общего файла констант и без «магических» значений. Лимиты шлюзов это публичные константы, и тесты ссылаются на них, а не дублируют числа.
- **Без Docker на этом шаге.** Для консольной команды без базы и сети хватает PHP и Composer. Docker Compose появится вместе с БД и брокером (см. план ниже).

## Проверки

```bash
composer test    # PHPUnit: unit-тесты, тесты команды и проводки контейнера
composer stan    # PHPStan, уровень 8
composer cs      # PHP-CS-Fixer, стиль PER-CS (преемник PSR-12), только проверка
composer cs:fix  # то же с исправлением
composer check   # всё вместе
```

Автозагрузка по PSR-4. Тест `ProcessPaymentCommandWiringTest` поднимает настоящее ядро и проверяет, что контейнер собрал команду, use case, фабрику и все три шлюза.

## Ограничения этого шага

- Шлюзы это заглушки: нет сети, нет реальных провайдеров.
- Лимит сравнивается в минорных единицах независимо от валюты, для заглушки этого достаточно.
- `Money` рассчитан на валюты с двумя знаками после запятой (RUB, USD, EUR). Для JPY или KWD формат придётся доработать.

## Как планирую развивать

1. **Реальные адаптеры шлюзов** на Symfony HttpClient в слое Infrastructure. Секреты через переменные окружения, таймауты и ограничения повторов в конфигурации.
2. **Хранение платежей** в Doctrine: агрегат `Payment` с жизненным циклом `created → pending → approved / declined` и **идемпотентностью** по ключу, чтобы повторный запрос не списывал деньги дважды.
3. **Webhook'и провайдеров** и нормализация их статусов к нашим.
4. **Маршрутизация и fallback**: приоритеты шлюзов для одного способа оплаты, переключение на запасной шлюз, circuit breaker.
5. **Symfony Messenger** для асинхронных подтверждений и повторных попыток.
6. **Наблюдаемость**: логи по PSR-3 с идентификатором платежа, метрики по отказам и времени ответа шлюзов.
7. **HTTP API**: контроллер поверх того же use case `ProcessPayment`. Порты уже готовы, домен и приложение не меняются.
8. **Docker Compose и CI** (GitHub Actions: тесты, PHPStan, CS на нескольких версиях PHP), когда появятся БД и брокер.
